# Skills maintenance — `.opencode/skills/`

12 skills, 4,893 lines. Orchid pack 442–600 each. This file covers upkeep only, not usage.

## Two families

- `orchid-*` (8): hand-authored in this project. Source-verified against
  orchidsoftware/platform master Sep-2026. Online docs at orchid.software lag the code.
- `openspec-*` (4): GENERATED by openspec CLI (`metadata.generatedBy: "1.4.1"`).
  Never hand-edit. Regenerate via CLI.

## Orchid frontmatter contract

Keep on every edit or addition. Verified shape: `head -20 <skill>/SKILL.md`.

- `name`: must equal dir name, kebab-case.
- `description`: double-quoted single line, 150–380 chars. Pattern: capability
  + "Activate when working with…" + "Do not use for…".
- `license: MIT`, `compatibility: opencode`.
- `metadata`: author `orchid`, version `"1.0.0"`, domain `backend`,
  framework `orchid-platform-14`, triggers, role `specialist`, scope `laravel`,
  `related-skills` (must name existing siblings only).

## Skeleton invariant

- First H2 is always `## Version notes` (platform skills: mined from `upgrade.md`;
  orchid-crud: mined from crud CHANGELOG). Check: `grep -m1 '^## ' */SKILL.md`.
- Closing block, in order: `## This project (medical-orchid)` → `## Anti-patterns`
  → `## Reference`. Check: `grep '^## ' <skill>/SKILL.md | tail -3`.

## Evidence rule

Every class/method claim must be greppable in installed platform source
(`vendor/orchid/platform/src`) or the clones. Source wins over docs.
Unverifiable APIs are omitted, never guessed. Keep current:

- `config/orchid.php`, not `config/platform.php` as docs say.
- `Attach`/`Picture`/`Cropper` exist; no Upload/Images/Relation/Repeatable classes.
- `Orchid\Access\PermissionGroup::make()/add()`; ItemPermission deprecated.
- `TD::sort()`, no `sortable()`. `Layout` via `Orchid\Support\Facades\Layout`.
- `Dashboard::allowedPermissions()`; no `getAllowAllPermission`.
- `TextArea`, not `Textarea`. Crud hooks `save`/`delete`.
- Crud provider reads `config('platform.*')` while platform publishes `config/orchid.php`.
